## 一、汇报要点

**核心判断：** 产业套保客户采购现货数据终端，本质需求并非行情浏览，而是将市场价格波动转化为可执行的成本、库存、利润与风险敞口管理。若产品继续按金融投研终端逻辑扩展指标，将更好服务研究员，而难以服务真正付费的产业经营人员。

**产品定位建议：** 产业价格与风险管理操作系统。以场景组织功能，以基差为核心对象，按客户能力分层交付，以现货经营语言表达套保结果。

**提请确认的三件事：**

1. 确认上述产品定位，避免与期货交易软件、金融投研终端同质化竞争。
2. 确认按「看价版 / 经营版 / 期现版」分层建设，优先服务 L1–L2 客户体验，以接口与口径能力承接 L3–L4。
3. 确认近期资源集中于五项能力：个性化工作台、多口径基差、Excel 插件、经营计算器、套保效果报告。

## 二、研究范围与结论

本汇报围绕四个问题展开：

| 序号 | 问题 | 结论 |
| --- | --- | --- |
| 1 | 产业套保用户需要何种数据、对应何种业务场景 | 刚需为可对账的现货价格、基差与升贴水、库存仓单、成本利润；进阶为自有库存、合同与期货头寸合成的净敞口。使用场景按经营节奏展开，而非按数据目录展开。 |
| 2 | 使用数据终端时期望获得何种数据与功能 | 数据侧重合同口径价格与基差；功能侧重工作台、导出、预警、经营测算、敞口汇总及管理层报告。交易执行非现货终端主战场。 |
| 3 | 多数客户专业水平如何 | 现货业务熟练，期货工具半熟练，套保规模受制度与人才约束。付费主体集中于 L1–L2，标杆客户集中于 L3–L4。 |
| 4 | 对套保的接受程度如何 | 龙头品种与大型企业接受度较高；数量占优的中小客户仍将套保等同于投机。产品须按接受度分层切入，不可默认用户已具备套保共识。 |

## 三、客户结构

### （一）产业链角色

产业套保需求产生于实货流转中的价格风险，同一产业链上目标不同，不可按单一「套保户」设计产品。

| 角色 | 典型主体 | 主要风险 | 套保方向 | 决策目标 |
| --- | --- | --- | --- | --- |
| 上游生产 | 矿山、钢厂、电解铝、炼厂、农产品加工 | 产成品价格下跌 | 卖出保值 | 锁定销售价格，稳定库存价值 |
| 中游加工 | 压榨、铜杆、镀锌、化工深加工 | 原料与成品价差收窄 | 加工利润锁定 | 判断开工可行性，锁定加工利润 |
| 贸易流通 | 钢材、有色、油脂油料、能源贸易 | 库存贬值、点价错配、资金占用 | 库存保值、基差贸易 | 判断采购与出货节奏，管理点价窗口 |
| 下游采购 | 制造、家电、汽车、施工、食品 | 原料上涨、订单锁价后成本失守 | 买入保值、远期采购 | 锁定到厂完全成本，控制锁价比例与期限 |

### （二）终端实际使用者

日常使用者通常不是专职期货交易员，而是：

| 岗位 | 使用目的 |
| --- | --- |
| 采购、销售 | 询价、比价、定价、点价 |
| 期现、风控（中大型企业） | 基差跟踪、敞口核对、日报编制 |
| 财务、董事会办公室 | 套保效果评价、合规与审计口径 |
| 企业负责人、分管领导 | 判断是否锁定风险、期现合并后是否改善经营结果、是否构成投机质疑 |

执行岗位与决策岗位必须同时被服务，但不应使用同一信息架构与同一表达口径。

## 四、数据需求

产业客户数据需求分为四层。现货终端的差异化能力在第一、二层的口径深度，以及第三层与企业自身数据的衔接。第四层决定大型客户能否将终端从查询工具升级为风险管理工具。

### （一）市场价格层（每日刚需）

| 数据项 | 说明 |
| --- | --- |
| 区域现货价格 | 按市场、规格、到厂 / 出厂 / 仓库价区分 |
| 厂提价、挂牌价、成交价 | 报价与成交须分列，避免有价无市 |
| 升贴水、品牌升水、地区价差 | 合同谈判与点价的直接依据 |
| 指数价格、结算基准价 | 部分合同挂钩第三方基准，属于结算工具 |
| 期货价格 | 须覆盖主力、指定合约、近远月结构，不可仅提供单一连续价 |
| 期现基差 | 现货减期货；须支持现货口径与合约口径的选择 |

**原则：** 价格序列必须可映射至合同口径（地区、规格、含税、交货地、对应合约）。无法对账的价格不具备套保使用价值。

### （二）基本面层（解释价格变动）

| 数据项 | 主要内容 |
| --- | --- |
| 库存 | 社会库存、厂库、港口、交割库、仓单；宜拆分至地区或仓库 |
| 供给 | 产量、产能利用率、开工率、检修、新投产 |
| 需求 | 下游开工、订单、表观消费、季节性 |
| 成本与利润 | 原料成本、加工费、冶炼 / 压榨 / 钢铁利润、进口盈亏 |
| 进出口与货流 | 海关、到港、进口溢价、内外盘价差、运费 |
| 交割 | 注册仓单、有效预报、交割品升贴水、交割成本 |
| 宏观与政策 | 仅保留可传导至该品种的项目，如汇率、出口退税、收储抛储、能耗约束 |

套保决策所依赖的，是少数能够改变近月基差的基本面变量，而非宏观指标的堆叠。

### （三）企业自身数据层（套保能否落地）

| 数据项 | 说明 |
| --- | --- |
| 自有库存 | 库内、在途、原料 / 在制品 / 成品 |
| 合同 | 已签未执行采购与销售、未完成点价量、定价公式 |
| 订单与排产 | 未来一至三个月确定量与预估量 |
| 衍生品头寸 | 账户、合约、方向、套保属性、保证金 |
| 三口径基差 | 市场基差、订单基差、库存基差 |
| 净敞口 | 未保值现货及合同，扣减已对冲头寸；按品种、月份、事业部分解 |
| 保值效果 | 期现合并盈亏，禁止仅展示期货端浮盈亏 |

市场数据完整但无法计算企业净敞口时，套保停留在观察阶段，无法进入管理阶段。

### （四）合规与审计层（低频，决定大型客户续费）

包括套保方案与额度、每日结算快照、历史重算、操作留痕、被套期项目与有效性测试、国资及上市公司信息披露口径。该层缺失时，国有企业与上市公司难以将终端纳入正式风控流程。

## 五、业务场景

产品应按经营事件组织，不宜按「价格 / 库存 / 资讯」等数据目录组织。

| 场景 | 业务问题 | 终端应提供的能力 |
| --- | --- | --- |
| 日常定价 | 本地区、本规格价格变动及可谈判空间 | 品种、区域、规格维度的当日价格视图 |
| 点价与基差贸易 | 升贴水是否合理，点价后期货腿是否完成对冲 | 基差历史、季节性、分位数、升贴水报价、点价进度 |
| 库存保值 | 库存市值、持货成本与可变现价格是否匹配 | 库存市值、保值比例、基差变动敏感度 |
| 采购成本锁定 | 销售已定价、原料未采购时的敞口与锁价比例 | 到厂完全成本测算（期货价格、升贴水、运费、资金、损耗） |
| 销售与加工利润锁定 | 原料已采购、产品未销售时的加工利润 | 分行业利润公式模板及当日价格代入 |
| 换月与期限结构 | 近月到期后的移仓成本与交割风险 | 合约日历、移仓成本、期限结构、交割品升贴水 |
| 风险预警 | 基差、库存、敞口、进口盈亏等突破阈值 | 按岗位推送，而非依赖专人值守大屏 |
| 复盘与审计 | 套保是否改善经营结果 | 期现合并报告，表述为锁定成本或锁定利润 |

## 六、终端功能需求

### （一）数据期望

1. 本企业关注品种、地区、规格的价格，而非全国单一均价。
2. 可选择现货口径与期货合约的基差。
3. 时效可满足经营决策的库存与仓单。
4. 可解释挺价或降价行为的成本与利润。
5. 可用于点价的升贴水及成交样本。
6. 有色、能源、农产品所需的内外盘、汇率与进口盈亏。
7. 与品种绑定的短讯，而非综合财经资讯。
8. 企业合同、库存与头寸的接入能力。

### （二）功能优先级

| 优先级 | 功能 | 产品形态 |
| --- | --- | --- |
| P0 | 个性化工作台 | 按品种、区域、岗位生成首页，替代数据目录首页 |
| P0 | 可信价格与基差 | 多口径价格、升贴水、历史分位 |
| P0 | 导出与表格衔接 | Excel 插件、增量刷新、落地库或 API |
| P0 | 预警 | 阈值预警、异常检测、企业微信或钉钉触达 |
| P1 | 经营计算器 | 钢铁、压榨、电解铜、PTA 等行业模板 |
| P1 | 敞口与保值比例 | 库存、合同、期货三表合成 |
| P1 | 点价辅助 | 升贴水历史、点价台账 |
| P1 | 套保效果报告 | 期现合并盈亏及基差贡献分解 |
| P2 | 研究工具 | 季节性、相关性等，默认收纳于高级功能 |
| P2 | 协同与权限 | 岗位权限、审批、操作留痕 |
| P2 | 研究支持 | 品种日报、专家问询；如采用生成式解读，须可追溯至原始序列 |
| P3 | 交易下单 | 以对接现有交易系统为主，不作为产品主线 |

### （三）边界

1. 不以金融投研终端的功能树作为产业客户默认界面。
2. 不以期货交易执行作为竞争方向。
3. 不以指标数量作为核心竞争力；不可比、不可对账的数据构成负资产。
4. 默认导航使用经营语言，衍生品专业参数置于高级选项。

## 七、客户能力评估

### （一）分层结构

| 层级 | 占比（约） | 特征 | 对产品的含义 |
| --- | --- | --- | --- |
| L1 | 40% | 现货经营熟练，不掌握合约、保证金、移仓；主要工具为即时通讯与电子表格 | 默认体验必须简单，提供价格、库存、简报与计算器 |
| L2 | 40% | 了解基差概念，难以核算自身库存基差；套保比例缺乏定量依据；数据分散于多个系统 | 需要基差、季节性、预警及简易敞口 |
| L3 | 15% | 已建立套保制度与额度，执行仍大量依赖手工；需要三口径基差与审计留痕 | 需要 API、自定义指标、权限与日报模板 |
| L4 | 5% | 已建设或采购商品交易与风险管理系统 | 以数据质量、口径文档、延迟与可重算为签约条件，界面非关键 |

上述比例因品种而异。有色、油脂油料、铜铝加工偏高；建材、煤炭及部分化工偏低。付费规模在 L1–L2，标杆效应在 L3–L4。

### （二）设计原则

1. 默认体验按 L1–L2 设计：三分钟内到达「本企业品种、本地区价格及基差」。
2. L3–L4 通过模块与接口升级，不强制进入复杂导航。
3. 从 L1 到 L2 的转化关键，是完成一次可理解的完全成本或利润测算，而非直接销售交易模块。

## 八、套保接受度

### （一）总体判断

接受度趋势向上，但「口头认同、实际执行、放大规模」三者不可等同。价格波动、汇率波动与利润收窄推动企业由价格判断转向利润锁定。《期货和衍生品法》及信息披露规则完善后，上市公司参与套保的数量持续增加。有色、家电、化工、油脂等产业链参与率高于一般制造业。基差贸易与点价在铜、铝、钢材、豆粕及部分能源化工品种中，已成为定价方式，而非附加金融操作。

### （二）主要约束

| 约束类型 | 具体表现 | 产品含义 |
| --- | --- | --- |
| 认知 | 将套保等同于亏损或投机；外部报道常单独披露期货亏损 | 效果展示必须期现合并，默认使用现货经营语言 |
| 组织 | 采购、销售、期货、财务考核目标不一致 | 需要分角色视图及统一的效果评价口径 |
| 能力 | 中小企业缺少专职人员，决策依赖个人经验 | 需要明确的锁价比例、期限与贵贱判断 |
| 合规 | 国有企业在支持套保的同时实行严格额度与方向管控 | 额度、套保认定与留痕属于基础功能 |
| 工具 | 期现数据割裂，电子表格对账耗时长，敞口更新滞后 | 统一口径优先于新增图表 |
| 策略 | 多数企业仅能执行期现对应的基础保值 | 先保证简单套保可完成、可解释，再提供跨品种与期权工具 |

### （三）市场分层与销售口径

| 接受度 | 典型客户 | 产品切入点 |
| --- | --- | --- |
| 高 | 有色、油脂油料、铜铝加工、大型贸易、上市制造业原料采购 | 基差、点价、接口、敞口 |
| 中 | 钢厂、化工、煤炭、农产品加工 | 利润测算、锁价建议、预警、管理层报告 |
| 低 | 中小贸易、地方工厂、施工企业采购 | 价格与库存能力；套保仅以成本锁定测算与培训进入 |

对低接受度客户，价值主张应表述为稳定采购成本与库存价值，而不是推广衍生品交易。

## 九、现状问题

对照现有现货数据服务与产业交易系统，现货数据终端处于中间位置，主要问题如下：

1. **信息架构为目录型。** 按品种与数据类型切分，需用户自行拼装场景。
2. **基差停留在图表层。** 不能选择合同口径，不能连接企业自身货权。
3. **仅覆盖市场数据。** 企业仍以电子表格作为经营台账。
4. **两端能力不均衡。** 投研深度与采购执行效率均未形成明显优势。
5. **预警、移动端与协同弱。** 产业决策发生在即时通讯与例会中，而非个人计算机终端内。
6. **套保模块缺位或金融化过度。** L1、L2 客户难以进入。
7. **口径文档不足。** L3、L4 客户无法将数据接入核心系统。

## 十、优化方案

### （一）产品原则

1. 先场景、后数据。导航按盯价、点价、库存、锁成本、锁利润、风控、汇报组织。
2. 基差作为一等对象。任一价格默认附带对应合约、升贴水、历史分位及环比。
3. 以现货经营语言表达风险管理结果。默认输出未锁定数量及成本敞口；套保比率置于高级选项。
4. 分层交付、同一数据中台。看价版、经营版、期现版共用底层序列。
5. 将电子表格视为主要工作台之一，做好插件与导出。
6. 预警优先于看板。产业客户普遍不具备专职盯盘编制。
7. 交易执行与现有系统对接，不重复建设交易终端。

### （二）产品架构

| 版本 | 服务对象 | 核心能力 |
| --- | --- | --- |
| 看价版 | L1 | 个性化价格、区域升贴水、库存与简报、锁价测算 |
| 经营版 | L2（主战场） | 利润与成本计算、点价台账、预警订阅、套保效果报告 |
| 期现版 | L3 / L4 | 三口径基差、敞口引擎、API 与落地库、权限与审计 |

数据中台统一管理价格、库存、利润、仓单、资讯，并建立合同口径映射、计量单位、含税与交割品字典。

### （三）重点能力

**1. 个性化工作台**

首次使用采集品种、区域、岗位、规格。首页固定展示：当日价格（现货、期货、基差、升贴水）、库存与仓单变动、成本或加工利润、品种相关短讯、敞口或未锁定数量。全市场热力图不作为默认首页。

**2. 基差工作台**

支持现货口径（市场价、厂提价、指数价、用户合同价）与期货口径（主力、指定合约、加权）的组合。展示绝对基差、基差率、历史分位、季节性，以及与库存、仓单的叠加。支持预警、导出及升贴水分位提示。

**3. 经营计算器**

| 角色 | 输出 |
| --- | --- |
| 下游采购 | 锁定后到厂完全成本 |
| 上游销售 | 锁定后出厂净价 |
| 加工企业 | 吨加工利润 |
| 贸易企业 | 持货利润（现货变动、期货盈亏、升贴水变动、仓储资金） |

测算结果附带对应期货手数估算，作为从观察到执行的过渡，不替代交易系统。

**4. 轻量敞口**

先完成库存、未执行合同、期货持仓三表合成，输出按品种、按月份的净敞口、保值比例与额度占用。企业资源计划系统深度对接放入期现版，避免过早建设完整商品交易与风险管理系统。

**5. 预警与触达**

规则使用业务语言配置，例如基差分位、库存周增、未锁定量超计划、进口盈亏转负。触达通道以企业微信、钉钉、短信为先。

**6. 套保效果报告**

固定结构：现货端盈亏、期货端盈亏、基差贡献、合并结果，并与未套保情形对比。表达方式适配管理层阅读，降低因期货端单独亏损导致业务中止的组织风险。

**7. 数据口径字典**

每条价格序列须可查询采集时间、样本、含税、单位、规格、交货地、升贴水定义、与合同挂钩关系及历史修订记录。该能力是接口产品进入核心客户的前提。

**8. 内容与培训**

提供品种简报与「锁价条件」说明，按采购、贸易、工厂分角色路径。生成式内容必须回溯原始序列，不得给出无法核验的涨跌判断。

### （四）数据策略

竞争重点不在指标规模，而在少而准、可对账、可进入合同。

1. 每个重点品种做深六件套：价格、基差、库存、利润、仓单、进出口，保证日更与可追溯。
2. 区域与规格颗粒度优先于全国指数。
3. 升贴水与成交样本构成点价场景的差异化。
4. 期货行情以对接为主，补齐期限结构、仓单与持仓变化。
5. 开放企业自身数据入口（表格、接口、企业资源计划系统）。

### （五）商业策略

| 客户层 | 主售版本 | 转化方式 | 销售边界 |
| --- | --- | --- | --- |
| L1 | 看价版及锁价计算器 | 以采购成本优化案例转化 | 不演示复杂期现系统 |
| L2 | 经营版 | 以一次可被管理层读懂的复盘转化 | 不按金融终端模块拆卖 |
| L3 | 期现版、日报模板、权限 | 与风控及财务共同试点单一品种 | 不承诺替代企业资源计划系统 |
| L4 | 数据接口、落地库、口径服务等级 | 按序列质量与稳定性签约 | 不以界面作为主要卖点 |

统一话术：

1. 低接受度：说明当日采购与库存价值判断。
2. 中接受度：说明锁定后的真实成本及未锁定敞口。
3. 高接受度：说明市场、订单、库存三口径基差合并成册。

### （六）实施顺序

**第一阶段（改变默认体验）**

1. 个性化工作台  
2. 多口径基差、分位与预警  
3. Excel 插件稳定增量刷新  
4. 三至五个标杆品种的锁价与利润计算器  
5. 套保效果报告（敞口可先支持导入）

**第二阶段（形成经营版壁垒）**

6. 轻量敞口  
7. 点价台账与升贴水历史  
8. 企业微信、钉钉预警  
9. 口径字典与数据血缘  
10. 品种日报（人工加规则，再引入生成式辅助）

**第三阶段（按客户合同推进）**

11. 企业资源计划系统与交易终端对接  
12. 审批流、套保额度、会计凭证  
13. 跨品种对冲与期权结构  
14. 卫星及货流等增强数据，仅嵌入已有场景

## 十一、效果评估指标

产业终端不宜单独使用指标覆盖数或日活衡量。建议采用以下指标：

| 指标 | 定义 |
| --- | --- |
| 三分钟到达率 | 新用户三分钟内是否看到本企业品种、地区价格及基差 |
| 工作台留存 | 使用个性化首页用户的次日及七日留存，对比目录浏览用户 |
| 表格插件周活跃 | L2、L3 客户是否将终端作为周报数据源 |
| 预警回访率 | 被推送用户二十四小时内打开对应序列的比例 |
| 计算器至经营版升级率 | L1 用户使用锁价计算器后的付费转化 |
| 效果报告转发次数 | 作为组织内套保接受度改善的代理指标 |
| 核心序列投诉率 | 价格口径被客户质疑的次数，应下降 |
| 接口重算一致性 | 历史数据修订后能否完成对账 |

## 十二、提请决策

1. **定位：** 现货数据终端定位为产业价格与风险管理操作系统，不与交易软件竞争执行，不与金融终端竞争投研广度。
2. **结构：** 按看价版、经营版、期现版建设；默认体验服务 L1–L2，接口与口径服务 L3–L4。
3. **近期重点：** 工作台、多口径基差、Excel 插件、经营计算器、套保效果报告。
4. **资源约束：** 完整商品交易与风险管理系统、跨品种及期权能力，须在经营版形成留存后再投入。

以上方案供评审。通过后按第一阶段五项能力排期落地，并以三分钟到达率、插件周活跃及经营版升级率作为阶段验收标准。
