01 需求入口

销售 AI 对话采集

销售在提 OA 线索前/时，用一句话描述客户需求。AI 识别并结构化为「商品 + 数据项/信息项 + 周期」，并尽量匹配标准 ID；低置信时主动追问。

AI 介入要素

  • NER / 槽位抽取：商品、数据项、信息项、频率、时间窗、交付形态
  • 双目录匹配：数据项 ID / 信息项 ID（如 INFO-MEOH-WK）归一
  • 同义词归一：甲醇/MA、市场价/现货价、周评/周报 → 标准词典
  • 澄清策略 + 置信度门槛：缺槽位只问 1–2 问；低置信转人工
现状痛点销售口语描述散乱，PM 反复理解需求并手工落表
AI 后变化提交即带结构化标签与候选 ID，后续节点复用同一需求对象

02 初筛分流

智能初筛与线索结构化

对话结果进入咨询/初筛层：判断是否属于数据类项目，并决定是否进入产品管理部审核。同步把 OA 销售线索补全为可流转对象。

AI 介入要素

  • 项目类型分类：数据集成 / 数据加工 / 咨询非数据
  • 历史相似单召回：同商品+类型的成交结构作参考
  • 缺失字段补全建议：客户主体、交付方式、新签/续签
  • 红线规则：无法映射标准目录时标记「需人工深挖」
现状痛点咨询人工判断项目类型，信息在线下传递易丢
AI 后变化自动挂标签并路由；非数据类提前分流，不占 PM 产能

03 PM 判定

PM 只做集成 / 加工判断

PM 不再手工制作 Excel。核心动作收敛为：确认需求是否可由标准数据集成满足；若是，放行销售进入对应「商品+数据类型」筛选平台；若否，进入数据加工分支。

AI 介入要素

  • 路径推荐：基于目录覆盖、字段可配程度给出「集成优先」建议
  • 风险提示：多部门、非标口径、定制衍生字段 → 倾向加工
  • 证据面板：可映射字段清单、缺口清单、历史同类判定
  • 一键动作：确认集成后自动开通销售筛选工作台
现状痛点PM 既理解需求又制表，成为主瓶颈
AI 后变化PM 决策时长从「做表」变为「看证据点一下」

04 自助筛选

销售筛选平台 · 数据项 + 信息项

主链鱼骨不变：在「甲醇」空间内，销售分别勾选数据项（如市场价字段）与信息项（如甲醇周评）。两类均以标准 ID 匹配目录，AI 负责预填、释义与冲突校验，替代 PM 线下制表。

AI 介入要素

  • 双目录预填：对话槽位分别映射数据项 ID / 信息项 ID
  • 字段与资讯助理：口径/单位/更新频率，或报告频次与覆盖范围
  • 组合推荐：「同类客户常选市场价华东日度 + 甲醇周评」
  • 合法性校验：互斥条件、无数据/无报告区间提前告警
新增补充信息项与数据项并列筛选，均带 ID（例：INFO-MEOH-WK）
AI 后变化销售所见即所得；PM 仅在异常/无目录时介入

05 报价出表

自动报价 + 线下交付表

筛选确认后，系统直接产出报价单与可发给客户的标准 Excel/方案表（数据项字段 + 信息项清单一并落表）。后续「销售核对方案 → 提交审批」尽量变成确认动作。

AI 介入要素

  • 计价引擎：数据项 + 信息项 × 周期 × 商品线折扣 / 续签规则
  • 表格模板匹配：按历史线下表头自动落列与样例行
  • 方案说明生成：给客户的非技术语言摘要
  • 新签/续签分叉：续签按旧订单号复用并 diff 变更点
现状痛点报价与表格依赖 PM 手工；续签也需线下通知改单
AI 后变化筛选结束即出「价 + 表」；销售只做对错确认

06 闭环与底座

交付闭环 + 知识底座

报价出表之后的审批、开通权限、签约尽量自动化填单与状态追踪；底层用「商品 → 数据项/信息项 → 模板 → 计价」知识本体支撑前序节点。交付完成后可进入节点 07 做项目修改。

AI 介入要素

  • OA 审批单自动填报：客户、方案、报价、附件表
  • 开通与签约进度机器人：超时/驳回原因摘要
  • 知识图谱：商品→数据项ID / 信息项ID→模板→价规
  • 反馈闭环：销售改选项反哺推荐与词典
现状痛点后半段仍大量线下通知；前半段缺少统一主数据
AI 后变化后半段可确认化；交付后变更走节点 07 版本化审批

07 交付后变更

项目修改审批（版本化）

项目交付后若需更换数据项、信息项或数据周期，默认不新开线索，挂在原订单走变更单：修改 → 提交 → 审批 → 执行。系统生成补充版本（V1、V2…）。仅新客户 / 新商品线 / 改加工 / 超合同边界时，才引导回节点 01 新提需求。

改单 vs 新需求 · AI 介入

  • 同单换项/周期（目录可覆盖）→ 变更单，复用筛选与报价，跳过对话与 PM 判定
  • 更换数据项 / 信息项 / 周期：单个或多个，按 DATA-ID / INFO-ID
  • 边界场景（新商品线、改加工、超合同）→ 建议转节点 01 新需求
  • AI：路由建议 + diff 旧方案 + 重算报价 + 预填审批单
默认路径同单 Change Order → Vn，不新开线索号
版本规则不覆盖旧版；权限与交付按最新已通过版本生效
