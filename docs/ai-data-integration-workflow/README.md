## 目标

把当前流程中 PM 手工制表、线下来回确认的主路径，收敛为：

**销售自然语言提需 → AI 初筛 → PM 仅判定集成/加工 → 销售自助筛选（数据项+信息项）→ 自动报价与出表 → 交付后可版本化修改审批**

## 鱼骨节点

| 节点 | 角色 | AI 介入要点 |
|---|---|---|
| 01 需求对话采集 | 销售 | 实体抽取（商品+数据项/信息项+周期）、ID 匹配、澄清追问 |
| 02 智能初筛分流 | 咨询/系统 | 项目类型分类、相似单召回、OA 线索结构化 |
| 03 PM 类型判定 | 产品 PM | 集成/加工推荐+证据、一键开放筛选平台 |
| 04 筛选平台 | 销售 | 数据项 + 信息项双目录、字段/资讯释义、组合推荐 |
| 05 报价与出表 | 系统 | 计价规则、标准交付表生成、续签复用。**未入库或未定价项**先走 [入库定价线上流程](../ai-data-pricing-online-workflow/index.html)，五步通过后再合并进本节点报价 |
| 06 交付闭环底座 | 系统 | OA 预填、进度追踪、商品-数据/信息知识本体 |
| 07 项目修改审批 | 销售/PM | 默认同单 Change Order→Vn；边界场景才新开需求 |

## 本次补充需求

1. **信息项**：筛选不只有数据项；如「甲醇周评 · 即期一年」，以信息项 ID（例：`INFO-MEOH-WK`）匹配目录。
2. **交付后修改**：在交付闭环之后增加项目修改审批入口，覆盖：
   - 更换数据项（单个/多个）
   - 更换信息项（单个/多个）
   - 更换数据周期（单个/多个）
   - 版本规则：不覆盖旧版，生成 V1 / V2… 补充记录；交付按已通过版本执行。

## 交付后：改单还是新需求？

**默认不重新提线索。** 同客户、同合同内的项/周期更换，挂在原订单上走节点 07「项目修改（Change Order）」生成 Vn。

| 场景 | 入口 | 说明 |
|---|---|---|
| 同单内换数据项 / 信息项 / 周期（目录可覆盖） | **节点 07 变更单** | 复用筛选平台 + 报价引擎；跳过 01 对话采集与 03 PM 类型判定 |
| 合同到期续约、方案大体不变 | **续签路径** | 按旧订单号复用，diff 变更点 |
| 新客户 / 新商品线 / 集成改加工 / 超出现有合同商业边界 | **节点 01 新需求** | 重新走主链；可关联原订单作参考，但不覆盖原 Vn |

贯穿方式：变更单 = 在原订单上下文中再次进入 04 筛选 → 05 重算报价/出表 → 修改审批 → 06 按新版本同步权限与交付清单。

## 建议落地顺序

1. 先跑通标准数据集成主路径（示例：甲醇市场价 + 甲醇周评 · 即期 1 年）
2. 同步建设知识底座（商品 → 数据项 ID / 信息项 ID → 模板 → 价规）
3. 交付后变更走节点 07（默认变更单，边界场景才新开线索），与主链审批复用同一权限模型
4. 数据加工分支暂复用结构化需求，不在本阶段替代项目经理/分析师执行
