## 一、汇报要点

**核心判断：** 产业客户使用现货终端的瓶颈是信息过载、口径不一致、测算耗时、以及市场价格无法自动对上「本企业规格、本企业地区」。人工智能应嵌入上述瓶颈，承担过滤、对齐、解释与核对。本产品不生成套保方案，不给出开平仓、锁价比例或移仓计划。

**需求强度排序（由强到弱）：** 本企业口径的解读与摘要 → 测算与口径对齐 → 预警解释与经营核对 → 复盘报告生成 → 合同与点价要素抽取 → 情景推演。价格预测、自动交易、套保方案起草不作为产品能力。

**建议推进的方案：**

| 方案 | 名称 | 对应强需求 | 建议阶段 |
| --- | --- | --- | --- |
| 甲 | 本企业口径经营简报与异动解释 | 全国资讯与本企业规格、地区不对齐 | 第一阶段 |
| 乙 | 锁价与成本测算助手 | 算不清到厂完全成本与利润 | 第一阶段 |
| 丙 | 预警解释、相关性判定与经营核对 | 预警与本企业无关或看不懂，且无人专职盯盘 | 与预警同步 |
| 丁 | 经营结果报告自动生成 | 复盘耗时、口径冲突 | 第二阶段 |

**提请确认：**

1. 确认人工智能定位为「辅助观察、测算、解释、核对」，不产出套保方案，不替代询价、采购、出货决策。
2. 确认方案甲必须以企业规格、地区、交货地画像为生成前提，未配置画像则不得生成「与我相关」简报。
3. 确认预警端只做解释、相关性、经营影响与核对项，禁止输出锁价、开平仓、移仓等动作建议。
4. 确认所有生成内容必须可追溯至价格序列、库存或资讯原文。

## 二、适用原则

1. **先对齐本企业口径，再做摘要。** 未绑定规格、地区、交货地的内容，视为与客户无关，不得进入简报与预警正文。
2. **生成必须绑定证据。** 每一句结论须能点回数据点、样本口径与时间戳。无法引用则不得输出。
3. **用现货经营语言。** 默认表述为本规格价格、本地区到厂价、库存市值、升贴水；不使用套保比率、开平仓指令作为默认输出。
4. **人机分工固定。** 机器负责采集、映射、计算、摘要、核对提示；人负责采购、定价、出货及任何风险管理决策。
5. **本产品不承担套保方案。** 不生成分批锁价计划、移仓计划、开平仓建议、保值比例建议。
6. **按岗位交付。** 采购、销售、贸易、财务看到的是同一数据的不同经营表述，不是不同的交易策略。

下表按需求强度、数据条件、合规风险给出介入判断。本产品边界已收紧：方案起草类工作整项不做。

| 环节 | 岗位典型工作 | 人工智能可承担的工作 | 需求强度 | 一期建议 |
| --- | --- | --- | --- | --- |

| 7. 复盘 | 编制日报、月报 | 按本企业口径汇总价格、库存、成本或利润变动 | 中强 | 二期 |
| 8. 合规 | 核对数据口径与操作留痕 | 字段完整性检查 | 中 | 三期 |
| 9. 协同 | 向负责人说明本地价格与库存 | 将同一结果改写成采购、财务、负责人口径 | 中强 | 依附甲、丙、丁 |

## 四、方案甲：本企业口径经营简报与异动解释

### （一）要解决的问题

现有简报若按大类品种生成，产出的是全国或主产区价格，与客户真实经营对象不一致。产业客户关心的是：本企业采购或销售的规格、本企业工厂或仓库所在地区、本企业合同交货地。全国均价变动、外地库存变动，若不能映射到上述口径，对客户没有决策价值。

### （二）企业画像（生成前提）

简报与预警共用同一套画像，未完成配置则只提供市场总览，不宣称「与我相关」。

| 画像字段 | 说明 | 示例 |
| --- | --- | --- |
| 经营品种 | 大类及子类 | 螺纹钢、电解铜、豆粕 |
| 本企业规格 | 内部牌号、厚度、强度、含量等，须映射到市场规格 | 内部「HRB400E Φ18」映射为某市场「螺纹 18mm」 |
| 关注地区 | 采购地、销售地、工厂、仓库 | 杭州到厂、乐从仓库、无锡市场 |
| 交货与计价地 | 合同交货地、含税、到厂或出厂 | 含税到厂价，运费模板 |
| 对照基准 | 用于解释的全国或主产区序列 | 上海市场价、主力合约、指数价 |
| 岗位 | 采购、销售、贸易，决定简报侧重点 | 采购看进价与到厂成本，销售看出厂净价 |

映射规则须可维护：一对一、一对多（同一内部规格对应多个市场报价源）、地区替代（本地区无报价时，允许指定邻近市场 + 运费，并在简报中明示「替代口径」）。

### （三）能力范围

1. **按画像生成，不按品种目录生成。** 一页简报的主语是「本企业规格 × 本企业地区」，全国与主产区数据只作为对照栏，不得占据正文首位。
2. **规格对齐。** 展示本规格价格、与基准规格的升贴水、与可替代规格的价差。规格未映射时，该条不得写入简报。
3. **地区对齐。** 展示本地区（或指定交货地）价格、邻近市场价格、到厂完全价（本地区价 ± 运费模板）。外地价格变动若未传导至本地区，须明确写「本地区未跟涨 / 未跟跌」。
4. **库存与基本面对齐到地区。** 优先使用本地区或本仓库可对应的库存、到货、仓单；全国库存仅作背景。全国库存上升而本地区库存下降时，须并列写出，禁止用全国库存替代本地判断。
5. **资讯过滤。** 只保留涉及本品种、本规格、本地区或指定对照市场的短讯。政策、检修、限产若发生在无关产区，默认不进入简报，或列入「其他地区、与本企业无直接对应」。
6. **异动解释只陈述同期变化，且必须带口径。** 正确示例：本地区 Φ18 螺纹较昨日下跌 X 元，同期对照市场下跌 Y 元，本规格对基准规格升贴水走弱 Z 元，本地区社会库存持平。禁止：因此应当锁价或卖出保值。
7. **多主体企业。** 集团下多个工厂或仓库，按主体各出一页，或在一页内分栏，禁止混用地区口径。
8. **全部数字可回溯** 至序列的规格、地区、含税、交货地字段。

### （四）简报结构（固定）

| 板块 | 内容 | 口径要求 |
| --- | --- | --- |
| 本企业对象 | 规格、地区、交货地、岗位 | 来自画像，不可空 |
| 本规格本地区价格 | 现货、涨跌、到厂或出厂价 | 必须是映射后的序列 |
| 对照 | 基准市场、邻近市场、期货或指数 | 标明「对照，非本企业成交价」 |
| 本规格升贴水 | 对基准规格、对期货（如有） | 本规格，不得用大类均价代替 |
| 本地区库存与到货 | 可对应则展示，不可对应则标注数据缺口 | 禁止静默改用全国数 |
| 成本或利润 | 代入本地区运费与本规格价格 | 缺运费则留空并提示补全 |
| 相关短讯 | 已过滤 | 须能指向地区或规格 |
| 异动说明 | 同期变化列表 | 每条带规格、地区标签 |

### （五）交付、边界与验收

**适用客户：** L1–L3。L4 可作为按画像切片的接口摘要。

**交付形态：** 工作台首页（默认本企业口径）+ 企业微信 / 钉钉。不单独做开放域聊天。

**人机边界：** 机器完成规格地区映射、过滤、摘要；人决定询价、比价、采购或出货。不生成套保或锁价动作建议。

**验收：**

1. 简报首屏是否为本企业规格 × 地区，而非全国品种均价。
2. 规格、地区未映射条目的拦截率 100%。
3. 「外地变动、本地未变」类表述的口径正确率。
4. 用户「与我相关」评分；因套用全国口径导致的投诉数。
5. 引用可点击率 100%。

## 五、方案乙：锁价与成本测算助手

测算对象为到厂完全成本、出厂净价、加工利润、持货利润。计算由规则引擎执行，模型只收集参数、解释算式。参数须带入本企业规格与地区（运费、升贴水、损耗）。缺参数则停止，不得用全国均价填空。

不输出保值手数建议、锁价比例建议、开平仓建议。允许对照「本地区价格变动 50 元对到厂成本的影响」，作为敏感度，不作为交易方案。

## 六、方案丙：预警端人工智能（不做套保方案）

### （一）定位

预警端解决三件事：这条预警是不是本企业的事；若是，经营上意味着什么；接下来应核对哪些数据、通知谁。不解决「该不该套保、如何下单、锁多少」。

产业客户没有专职盯盘编制，阈值突破后常见结果是忽略，或在即时通讯中询问含义。若预警推送的是全国指标名称，或附带套保动作建议，前者会被关掉，后者超出本产品边界。

### （二）预警必须先过企业口径

与方案甲共用画像。一条市场预警进入客户之前，须完成相关性判定：

| 判定 | 处理 |
| --- | --- |
| 规格匹配 | 预警序列已映射到本企业规格，或为用户指定的对照规格 |
| 地区匹配 | 预警地区为本企业关注地、交货地，或为已声明的替代市场 |
| 传导匹配 | 全国或主产区异动已在本地区价格或本地区库存上出现，或明确「尚未传导」 |
| 岗位匹配 | 采购类预警不默认推送给仅负责销售的账号 |

判定结果为「不相关」则不推送，或进入低优先级汇总，不得占用主通道。判定为「仅对照市场相关」时，标题须写明对照口径，不得写成「你的价格已突破」。

### （三）预警卡片结构（固定四段，无第五段方案）

**1. 触发事实（规则引擎，禁止模型改写数字）**

- 指标名称、阈值、当前值、突破时间。
- 规格、地区、含税、交货地。
- 对照序列（若有）的同期值。

示例：本企业关注规格 HRB400E Φ18，杭州市场含税价较昨日下跌 80 元，触及用户设定的日跌幅阈值；对照上海市场下跌 30 元。

**2. 相关性说明（模型在模板内复述判定结果）**

- 与本企业规格、地区是否直接对应。
- 若为全国或外地指标：本地区价格、本地区库存是否同步变化；未同步则写「全国指标触发，本地区尚未出现同等变动」。
- 多工厂客户须写明击中哪一个主体。

**3. 经营含义（数字来自规则，模型只做句式）**

按岗位翻译为现货经营影响，不翻译为衍生品动作。

| 岗位 | 允许的含义表述 |
| --- | --- |
| 采购 | 本规格本地区进价变动对到厂成本的影响（已配置运费时可给金额） |
| 销售 | 本规格本地区出厂价或可售价格变动对毛利的影响 |
| 贸易 | 本地区升贴水或地区价差变动对持货市值的影响 |
| 共用 | 本地区库存可对应天数的变化（有库存数据时） |

禁止出现：建议买入 / 卖出保值、建议开平仓、建议移仓、建议锁价 X%、建议追加头寸。

**4. 经营核对项与通知（核对，不是方案）**

核对项只指向「去看什么、去问谁」，不指向「去做哪一笔套保」。

| 岗位 | 核对项示例 |
| --- | --- |
| 采购 | 核对本规格未执行采购合同的计价条款；核对今日供应商报价是否已跟市场；核对本地区到厂运费是否仍适用 |
| 销售 | 核对本规格在手订单锁价条款；核对本地区竞品报价 |
| 贸易 | 核对本仓库该规格库存数量与成本；核对本地区与对照市场的价差是否仍可覆盖运费 |
| 共用 | 打开本规格本地区价格序列；打开本地区库存；如连续触发，通知指定负责人 |

可附「打开工作台对应序列 / 打开计算器」的链接。不可附「生成套保方案」「一键锁价」。

### （四）预警端可做的人工智能能力（按优先级）

| 优先级 | 能力 | 说明 |
| --- | --- | --- |
| P0 | 相关性过滤 | 按规格、地区、主体丢弃无关预警，降低噪音 |
| P0 | 口径标注 | 每条预警强制展示规格、地区、含税、交货地；全国口径必须标明 |
| P0 | 触发解释 | 用经营语言复述规则结果，不改数字 |
| P0 | 本地 vs 对照拆分 | 全国触发而本地未变时，单独成类，避免误读 |
| P1 | 经营影响换算 | 将涨跌幅换算为本规格本地区成本或市值变动（依赖运费、库存等已配置参数；缺参数则只报价格，不报金额） |
| P1 | 核对清单 | 按岗位列出应核对的价格、合同、库存、报价来源 |
| P1 | 通知路由 | 按主体、岗位、连续触发次数升级至指定人，升级内容仍是解释与核对，不是方案 |
| P2 | 合并降噪 | 同一规格同一地区短时间多次触发，合并为一条，说明「重复触发 N 次，最新值」 |
| P2 | 数据缺口提示 | 本地区无库存或无成交价时，提示缺口，不得用全国数填入经营含义 |
| P3 | 预警规则用自然语言配置 | 「我的杭州 Φ18 日跌超过 50 元通知我」解析为规则，生成后须人工确认阈值与口径 |

### （五）预警端明确不做

| 不做 | 原因 |
| --- | --- |
| 套保方案、分批锁价计划、移仓计划 | 超出产品边界，且无法对经营结果负责 |
| 开平仓、加减仓、保值比例建议 | 易被理解为交易指令，合规与追责风险高 |
| 用全国预警直接推导本企业应当采购或出货 | 未完成规格、地区传导判定 |
| 处置策略库中的衍生品动作 | 核对项只保留经营数据与合同复核 |
| 预警后自动改写用户阈值以「优化套保」 | 阈值由用户或风控制度设定 |

### （六）交付、边界与验收

**适用客户：** L1 需先有本企业规格与地区画像及简单阈值；L2、L3 为主用户。

**交付形态：** 企业微信 / 钉钉 / 短信卡片，一键打开本规格本地区序列。主通道只推「相关」预警。

**人机边界：** 是否触发由规则判定；是否与本企业相关由映射表判定；如何造句由模型在模板内完成；是否调整采购、定价、库存，由人决定。

**验收：**

1. 无关规格或无关地区预警的主通道误推率。
2. 卡片是否同时具备规格、地区字段。
3. 「全国触发、本地未变」分类准确率。
4. 文案中套保 / 开平仓 / 锁价比例等禁用词的拦截率 100%。
5. 预警后 24 小时打开对应本企业序列的比例。
6. 因口径错误导致的关闭或投诉次数。

## 七、方案丁及可选能力

**方案丁：** 按本企业规格与地区汇总价格、库存、成本或利润，生成经营日报。不编制套保效果对照，除非客户自行导入衍生品数据且明确要求「期现合并展示」；默认版本仅为现货经营复盘。

**方案戊（可选）：** 合同与点价要素抽取，写入台账，服务定价与库存核对，不触发套保方案生成。

**方案己（可选）：** 本规格本地区价格或升贴水变动对到厂成本、持货市值的情景对照。不输出交易计划。

## 十、技术约束

1. **画像先行：** 规格映射表、地区列表、交货地、运费模板是简报与预警的共同依赖，纳入第一阶段数据工作，而不是模型提示词。
2. **双引擎：** 价格、涨跌、分位、经营金额由规则引擎计算；模型只做过滤说明与模板填空。
3. **强制口径字段：** 简报与预警无规格或无地区则不得发送「与我相关」内容。
4. **禁用词表：** 套保方案、开仓、平仓、移仓、保值比例、建议锁价等在预警通道拦截。
5. **数字核对：** 模型输出数字须与引擎字段逐项比对，不一致则阻断。
6. **日志：** 保留画像版本、映射规则、数据快照、模型版本，满足追溯。

## 十二、提请决策

1. **画像：** 批准「本企业规格、地区、交货地映射」为简报与预警的共同底座，未配置则不提供个性化生成。
2. **预警：** 批准方案丙按解释、相关性、经营含义、核对项四段交付；确认不包含套保方案与交易建议。
3. **边界：** 确认本产品不产出套保方案、开平仓建议、锁价比例建议。
4. **验收：** 方案甲以「首屏为本规格本地区」为硬指标；方案丙以无关预警误推率与禁用词拦截率为硬指标。
