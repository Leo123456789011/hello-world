# 量化决策项目一期、二期投入边界及红桃 3 承载说明

**阅读对象：** 产品管理部（资源锁定）、合作方四时投资（职责与交付落点）。  
**产品结论：** 面向量化交易场景的数据治理（可回测口径、交易日对齐、point-in-time、因子与回测验证）不属于卓创现有专业能力。现货采集与入库不构成量化可用数据包。一期自开数至回测验收，合作方须全程参与标准制定、加工与验收签字；卓创承担供数、接口封装、试用交付及红桃 3 承载。在合作方完成验收签字前，产品侧不以卓创名义表述「已具备量化数据治理能力」。

规划口径：一期对应红桃 3 基础版（交付形态：API + 回测验证报告；产品范围：①②④）。二期对应红桃 3 工具版（交付形态：产品端可视化；产品范围：在一期基础上增加 ⑤⑥）。四时编制不计入卓创项目组人头。

---

## 一、合作方交付物在红桃 3 中的承载

合作方产出一经产品验收，即作为红桃 3 对应模块或技能包的内容主体与数据源，纳入对客产品持续运营，而非项目结题材料。一期进入基础版；二期在同一数据字典与接口规范上扩展为工具版技能包及可视化。后续版本沿用该套字段与口径。

| 量化产品 | 对客交付规格 | 红桃 3 承载位置 | 合作方交付物的产品用途 |
|---|---|---|---|
| ① 通用量化基本面库 | 达口径品种之现货基本面可 API 抽取、可回测 | 基础版：数据底座 / 量化回测模块 | 合作方审定的数据字典及回测验证报告，构成该模块的数据本体与验证依据 |
| ② 分析师标注 | 主力品种重要性星级及方向（利多 / 利空 / 中性）；量化初测为配套交付 | 基础版：因子挖掘模块。工具版可复用为筛选类技能包 | 合作方提出初测阈值与标注规则，经产品冻结后由分析师执行；结果并入同一 API |
| ④ 单品种深度建模 | 品种专属因子包及回测摘要（农产品先行；生猪为已验证样板）；不含交易指令 | 基础版：单品种深度回测。工具版可复用为单品种技能包 | 模型及因子包由合作方研发并对其质量负责；卓创提供特色字段与 API 封装。端侧调用对象为已验收因子包 |
| ⑤ 舆情数据 | 可核验信源、时戳及方向 / 波动率 / 持续期；无法核验者不进入对客产品 | 工具版：舆情分析技能包及可视化 | 合作方输出的事件量化序列，为该技能包及可视化的内容来源 |
| ⑥ 多空强弱指数 | 品种日度综合指数、分项（买方意愿、卖方意愿、成交紧迫度、观望）及可回测历史 | 工具版：多空强弱技能包及可视化 | 指数计算方法及历史回溯由合作方负责；卓创保障沟通记录按公司模板入库 |

现行规划未列入 ③ 提前发布、⑦ 高频领先指标。③ 之发布链路可由卓创实施，策略窗口及时点标准须由合作方提出后方可对量化客户承诺时效。⑦ 之预估模型由合作方负责。未列入规划前，不对客户作出相应交付承诺；后续若纳入，适用同一数据字典与接口规范。

## 二、一期投入（红桃 3 基础版）

**功能规划：** 量化回测、因子挖掘。  
**产品范围：** ① 标准版、④ 高级版、② 分析师标注。  
**交付形态：** API + 回测验证报告。

### 2.1 编制

| 归属 | 角色 | 人数 | 是否计入卓创编制 |
|---|---|---|---|
| 合作方 | 四时对接及研发 | 2 | 否。人月在合作方资源清单中锁定 |
| 项目组 | 产品项目经理 | 1（陈然） | 是 |
| 项目组 | 研发项目经理 | 1 | 是 |
| 项目组 | 研发人员 | 3（数据、接口、终端） | 是。与红桃 3 / 红期融合共用 |

### 2.2 数据治理职责（一期核心，合作方全程参与）

| 工作项 | 验收标准 | 卓创职责 | 合作方职责 |
|---|---|---|---|
| 量化入库标准 | 对客数据包字段可对齐交易日、可回溯、可进入回测；未达口径的品种或字段不纳入对客包 | 按已冻结标准实施现货库开数（历史、增量、权限、出域），完成落表、版本管理及更新监控 | 制定并验收量化可用字段范围、缺失与修订规则、point-in-time 切分及交易日对齐规则。卓创不单独认定治理完成 |
| 数据字典 | 正式环境与测试环境字典一致，标杆客户可完成字段映射 | 依据字典实现接口、标准化数据包、鉴权及试用开通 | 编制并冻结字典（字段名称、频率、单位、更新截止时点）。字典为量化口径文件，区别于现货库表说明 |
| 清洗与可回测加工 | 客户无需二次清洗即可开展回测 | 按约定稳定供数；不修改合作方加工结果 | 承担清洗、对齐、因子化，并对数据包可回测性负责 |
| 回测验证报告 | 可作为标杆客户试用验收文件 | 以卓创名义将报告作为对客交付物发出 | 确定方法、完成回测、对样本外表现负责，并提交可对外披露的口径说明（样本、局限、免责）；不强制披露算法细节 |
| 开数范围 | 品种、字段、历史长度、更新频率、权限清单完整 | 现货库授权、缺数清单；与红桃 3 融合补数使用同一数据底座 | 提出量化侧必选字段及历史深度；缺口标注为不纳入对客包，不以资讯口径替代 |

一期数据治理的产品安排：合作方依据量化口径进入现货库协同治理；卓创负责出数稳定性与接口封装。非「卓创完成治理后再交合作方封装」。

### 2.3 分产品职责与红桃 3 承载

| 产品 | 验收标准 | 卓创职责 | 合作方职责 | 红桃 3 承载 |
|---|---|---|---|---|
| ① 基础库 | 四部达口径品种可 API 抽取；约 2 万条指标进入字典；约 2,000 条日频 / 周频刚需具备发布时间戳 | 供数、API、数据包、试用环境；终端完成基础版联调。一期不交付量化可视化页面 | 量化字典、清洗对齐、回测验证报告 | 基础版量化回测模块之数据本体 |
| ② 分析师标注 | 可售主力 20–30 个品种完成星级及方向标注（农业生猪、鸡蛋、苹果、红枣及能化甲醇优先占位）；不对全库约 2 万条逐条标注；标注不得表述为买卖点 | 产品排期；分析师按冻结规则标注；接口将初测与标注并入同一 API | 自动初测（夏普、IC 等）、提出初测阈值、拟定高价值标注规则，交产品冻结 | 基础版因子挖掘模块；工具版可复用为筛选类技能包 |
| ④ 单品种深度建模 | 农产品样板可交付回测摘要；不按全品种铺开；不交付交易指令 | 选品与验收；供给特色字段；分析师深访作为输入；API 封装因子包 | 建模、回测及因子包质量（黑盒）。未取得可验收输出前，产品不以卓创名义声称具备 ④ 能力 | 基础版单品种深度回测；工具版单品种技能包之内容来源 |

③ 若纳入一期协同：卓创可实施采集—入库—发布链路时点调整；合作方须给出策略窗口前的到达时点。未取得该时点标准前，③ 仅作为内部链路优化，不作为量化时效卖点。

### 2.4 项目组职责边界

| 角色 | 规划表职责 | 产品侧边界 |
|---|---|---|
| 四时对接及研发 2 人 | 因子与回测方法、加工及报告质量；向卓创提交可接字段及可对外口径说明 | 量化专业主体：治理口径、① 加工、② 初测、④ 模型；对标杆客户可用性负责 |
| 产品项目经理 1 人 | 立项、资源协调、研发范围及结果验收（API + 回测报告） | 冻结对客范围与验收标准；不审核算法；控制开数闸门；明确合作方交付物在基础版中的模块位置 |
| 研发项目经理 1 人 | 研发资源调度、项目管控 | 调度卓创 3 名研发及发版窗口；不替代合作方加工进度 |
| 研发（数据） | 数据字典落地、量化供数 | 按已冻结字典供数；不定义可回测标准 |
| 研发（接口） | API、数据包、试用环境 | 封装、鉴权、版本；不生产因子 |
| 研发（终端） | 基础版承载及融合 | 一期完成 API 与回测报告在基础版的接入；不交付工具版可视化 |

## 三、二期投入（红桃 3 工具版）

**功能规划：** 一期能力延续，并增加舆情分析（API 传输 + 可视化）。  
**产品范围：** ⑤⑥（规划所列）；①②④ 转入运维，不在二期重复建设数据治理底座。  
**交付形态：** 产品端可视化。

### 3.1 编制与职责边界

| 归属 | 角色及数量 | 职责边界 |
|---|---|---|
| 生产部门 | 分析师 20 人（可增项目经理 1 人） | 按规则提供标注、品种口径及每日沟通记录等原料；不承担量化方法研发。增配项目经理时，仅负责排期与抽检 |
| 生产部门 | 方法论部门 2 人 | 将合作方提交的可对外方法论转化为卓创对客表述（高价值规则、样本、局限、免责）；不制定因子或指数计算公式 |
| 支持部门 | 数据监管 1 人、信息安全 1 人 | 数据进出账、时戳、出域范围及密钥；不拆解合作方模型 |
| 支持部门 | 合规 1 人 | 免责声明、非投资建议、情绪类数据商品化及信源授权审查。专户、交易信号不纳入本期产品范围 |
| 项目组 | 一期班底延续，含合作方 2 人 | 终端迁移完成后再实施可视化；⑤⑥ 方法与序列仍由合作方按黑盒交付 |

### 3.2 分产品职责与红桃 3 承载

| 产品 | 验收标准 | 卓创职责 | 合作方职责 | 红桃 3 承载 |
|---|---|---|---|---|
| ⑤ 舆情数据 | 信源可核验，具备时戳及方向 / 波动率 / 持续期；无法核验者不进入对客产品 | 信源接入与结构化、推送 API、工具版展示、合规审查对客表述 | 事件量化方法（黑盒）。未取得可验收输出前，工具版不发布舆情技能包 | 工具版舆情分析技能包及可视化 |
| ⑥ 多空强弱指数 | 日度综合指数、分项及可回测历史完整 | 分析师按公司模板记录买 / 卖意愿、成交紧迫度、观望（⑥ 的必要输入，原始沟通内容不出域）；记录结构化、指数 API 及端侧展示 | 分项与综合指数计算方法及历史回溯（黑盒）。每日记录机制未运行则不开工 | 工具版多空强弱技能包及可视化 |
| ①②④ 延续 | 基础版持续稳定供数；工具版完成已有 API 的技能包化调用 | 运维、鉴权、端侧接入 | 口径变更由合作方提出并书面确认，避免并行两套字典 | 工具版为对一期模块的界面调用，不形成第二套数据 |

二期不新建数据底座。⑤⑥ 的字段、更新频率与历史长度由合作方定义；卓创在一期字典上扩展。方法论岗位审核对客表述合规性，不替代合作方量化专业能力。

|---|---|---|---|---|---|---|
| 一期 | 基础版 | API + 回测验证报告 | ①②④ | 产品项目经理 1 人、研发项目经理 1 人、研发 3 人；现货开数、API 及试用环境；分析师按 20–30 个主力品种排期标注 | 四时对接及研发不少于 2 人：量化入库标准、字典、加工、回测及 ④ 模型。编制在合作方 | 基础版量化回测模块、因子挖掘模块、单品种深度回测 |

## 五、需与合作方书面确认的事项

1. **数据治理：** 一期自开数之日起，合作方参与量化入库标准、数据字典及回测验收的制定，并完成签字确认。卓创负责现货出库与接口实现，不单独认定量化治理完成。  
2. **模型边界：** ④⑤⑥ 之方法与模型由合作方研发，卓创按输出物验收。卓创负责原料供给、数据出域、API 封装、红桃 3 承载及合规审查。未取得可验收交付物前，卓创不以自身名义声称已具备相应产品能力。  
3. **产品承载：** 合作方交付物构成红桃 3 模块与技能包的内容主体。一期承载于基础版量化回测、因子挖掘及单品种深度回测；二期承载于工具版舆情分析、多空强弱技能包及可视化，并纳入产品持续运营。后续版本沿用同一数据字典与接口规范。
