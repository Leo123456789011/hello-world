02 并行货架 · 散装 重点做

散装单数据项，AI 按条件筛选

客户用自然语言给出商品、区域、频率、时间窗，AI 从标准目录筛出可勾选数据项并加入购物车。客户只看见「要哪些数据」，看不见集成/加工标签。

AI 介入

  • 条件 → 目录命中（商品 / 区域 / 频率 / 时间窗）
  • 输出可勾选清单（带数据项 ID）
  • 缺口追问：只要现货，还是也要期货结算

明确不做

  • 不让客户二选一「集成 / 加工」
  • 选品过程中销售不插入接管

03 并行货架 · 元件 轻量做

场景数据元件（采购 / 期货 / 期现…）

元件是内部已经预组好的「该场景必要数据项」，方便客户按场景一看即买。它不是另一种订单类型，可以和散装、数据包放进同一张购物车。

AI 介入

  • 场景名检索、相近场景推荐
  • 打开即可看到预组数据项 ID

明确不做

  • 不现场让模型现编一套元件
  • 不与散装互斥下单

07 销售接手 重点做

系统建议集成 / 加工；沟通后可拆单

销售接收商场草稿单。系统按行给出建议：命中标准数据项且可 API → 集成；没有标准项、需分析师生产、线下交付（走加工交付规则）→ 加工。与客户沟通后，销售拍板：整单集成、整单加工，或拆成两部分走内部。清单与参考价仅作草稿，内部仍走完整主链。

AI 介入

  • 逐行命中标准项、能否 API，给出证据（ID / 交付形态）
  • 生成拆单草稿：集成内部单 + 加工内部单，挂原商场单号

明确不做

  • 不替代销售与客户沟通后的最终选择
  • 不跳过内部完整流程（集成从线索/筛选重做；加工从需求拆解重做）

落地建议：先做 02 散装 AI 筛选与 05 参考报价，再做 07 销售路径建议与拆单草稿。 03 / 04 以预组陈列和检索为主；06 只做草稿单和销售通知。 01 登录与选品中销售接管均不做。 商场不是第三条履约链：有标准项且可 API 进数据集成主链，需分析师生产且线下交付进数据加工主链。
