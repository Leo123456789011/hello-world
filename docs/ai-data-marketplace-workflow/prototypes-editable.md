# 数据元素商场 · 可编辑原型文案

> 用法：直接改下面文字；可贴进 PPT / PRD。  
> 主路径示例：**城燃贸易客户 · 散装 LNG 现货 + 期现结合元件 + 天然气数据包 · 参考价后下单链接销售**

---

## 0. 一句话主路径

客户登录数据元素商场  
→ 按需混选散装单数据项（可 AI 辅助）、场景元件、分析师数据包（包/元件只是分场景陈列，可同时买）  
→ 系统给出简单参考报价（非正式成交价）  
→ 客户下单，草稿内部单链接给销售  
→ 销售在系统建议辅助下判断集成或加工，必要时与客户沟通后整单走一条路或拆成两部分  
→ 清单与参考价作为草稿，分别进入数据集成或数据加工完整内部流程  

客户不对「加工 / 集成」做判断。选品过程中销售不随时接管。

---

## 0.1 AI 优化节点（可贴进评审，对标集成/加工那张表）

### 三条主逻辑

1. **客户自助选品**：混选散装（AI 按条件筛）、场景元件、分析师数据包。包和元件只是分场景陈列。
2. **参考报价后下单给销售**：简单参考报价（非正式成交价）→ 草稿内部单链接对口销售。选品中销售不接管。
3. **销售判定后再进内部主链**：标准项可 API → 集成；需分析师生产且线下交付 → 加工。沟通后可整单或拆两单。

### 节点对照

| 节点 | AI 做什么 | 人做什么 |
|---|---|---|
| 1 登录进入商场 | 不上模型 | **客户：** 用现有账号进入，看到三个货架 |
| 2 散装数据项 AI 筛选 | 抽商品/区域/频率/周期，目录命中，缺口追问，给出可勾选数据项（不向客户标路径） | **客户：** 自然语言提条件并勾选加购 |
| 3 场景数据元件 | 场景检索与相近推荐；组合已预生成，不现场编 | **客户：** 按采购/期货/期现查看预组项并加购，可混装 |
| 4 分析师数据包 | 包名检索、包内说明摘要；不替代打标打包 | **客户：** 查看已打标包（如天然气包）并整包加购 |
| 5 混装清单与简单报价 | 按价规汇总参考价；重复项提示。不生成正式合同价 | **客户：** 确认混装清单后提交，不选集成/加工 |
| 6 下单链接销售 | 生成草稿内部单、去重摘要、销售通知草稿 | **客户：** 提交/可留言；**销售：** 接收订单（选品中不接管） |
| 7 销售判定集成/加工 | 逐行判断标准项能否 API，建议集成或加工，生成拆单草稿 | **销售：** 沟通后拍板整单集成 / 整单加工 / 拆成两单，转入内部主链 |

## 节点 03｜场景数据元件（轻量做）

### 说明文案

## 节点 07｜销售判定集成 / 加工（重点做）

### 页面标题
销售工作台 · 路径建议

### 系统建议（客户不可见）

| 行 | 标准项 / API | 建议 |
|---|---|---|
| DATA-LNG-EC-SPOT 等目录项 | 是 / 可 API | 集成 |
| 期现结合元件内项 | 是 / 可 API | 集成 |
| 天然气数据包内项 | 是 / 可 API | 集成 |
| 客户留言「要按我司口径重做开工率」 | 否 / 需分析师+线下 | 加工 |

### 销售拍板（与客户沟通后）
- 整单走集成（仅保留标准项）
- 整单走加工（全部按加工交付规则、线下提供）
- **拆成两部分**：标准项 → 数据集成内部单；需生产项 → 数据加工内部单

### 按钮
- 接收订单
- 按建议拆成两单
- 全部改走加工
- 转入内部主链（草稿作附件）

### AI 介入要素
1. 逐行命中标准数据项、能否 API
2. 给出集成/加工建议与证据（ID、交付形态）
3. 生成拆单草稿（两张内部单号，挂原商场单）

### 明确不做
不替代销售与客户沟通后的最终路径选择；不跳过内部完整流程。

### 交接
- 集成单：从数据集成「线索 / 筛选」重走，商场清单仅参考
- 加工单：从数据加工「需求拆解」重走，商场清单仅参考

## 附录｜评审口径

数据元素商场是面向客户的选品层，不是第三条履约链。  
客户只负责选（散装 / 元件 / 包可混）和看简单参考价，然后下单给销售。  
集成 vs 加工由销售判定：有标准项且可 API → 集成；要分析师生产且线下交付 → 加工；沟通后可整单或拆两单。  
商场价不是成交价。内部仍走原集成、加工完整流程。  
AI 优先打在散装筛选、参考报价、销售路径建议三处。
