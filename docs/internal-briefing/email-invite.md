## 一、背景

我们现有数据交付，主路径仍是**销售接单、内部流转**：销售收集客户需求后，由咨询/PM 判断走哪条履约链，再进入筛选、报价、审核、开通或生产。这条链已经跑通，但大量时间耗在「听懂需求、拆成可执行的数据项、手工出方案」。

对应两条内部履约链，我们已经分别做了 AI 介入方案：

1. **数据集成**：客户要的是目录里已有的标准数据项/信息项，且可 API 交付。目标是销售自然语言提需 → AI 初筛 → PM 只判定「集成还是加工」→ 销售自助筛选 → 自动报价与出表。
2. **数据加工**：目录盖不住、需要分析师按客户口径生产，并走线下交付和加工自己的交付规则。目标是需求结构化拆解、产能协同、自动报价出方案；分析师制表、财务/合同审核仍保持人工。

与此同时，客户侧也出现了新入口：客户并不想先搞懂「集成 / 加工」，只想自己挑数据。因此补了第三条、只面向客户的选品层：

3. **数据元素商场**：客户可混选散装数据项（可 AI 按条件筛）、场景元件（采购 / 期货 / 期现等预组）、分析师数据包（如天然气包）。系统给出**简单参考报价**后下单，订单链接销售。客户不判断集成还是加工；销售接手后，由系统建议、销售拍板，再进入上面两条内部主链。商场清单和报价只作草稿，非正式成交价。

三套方案不是三条平行履约链，而是：**商场负责客户选品，集成/加工负责内部履约**。

## 二、目的

本次汇报希望对齐四件事：

1. **一张总图**：客户入口（商场）和内部两条履约链（集成、加工）如何衔接，各自从哪一节点进、到哪一节点出。
2. **AI 做 / 不做边界**：哪些节点重点做（筛选、参考报价、路径建议、需求结构化、自动报价），哪些只做轻量辅助，哪些明确不做（登录鉴权、财务/合同审核、分析师生产、选品中销售接管、替代 PM/销售拍板）。
3. **责任人不变**：AI 出草稿和建议，集成/加工的最终判定、产能接单、商务确认、合规审核仍由人拍板。
4. **下一步**：请与会同事对口径提出修改意见，并确认优先落地的节点，便于排期。

## 三、要解决什么问题

| 现在的痛点 | 方案打算怎么解 |
|---|---|
| 需求靠口述和线下传表，PM 手工拆项、制表，来回确认慢 | 集成侧：对话采集 + 筛选平台 + 自动报价出表；加工侧：需求结构化拆解 + 自动报价方案 |
| 「集成还是加工」边界不清，客户也没有判断力 | 客户不判。系统按「是否标准项、能否 API」给销售建议；销售沟通后可整单或拆成两单 |
| 只有销售驱动入口，客户无法自助看清能买什么、大概多少钱 | 商场：散装 AI 筛选 + 场景元件 + 分析师数据包，给出参考价后把草稿单交给销售 |
| 担心 AI 越界：替代分析师生产、自动过财务/合同、或在选品中插销售接管 | 会上一并亮出「明确不做」清单，先对齐边界再谈排期 |
| 商场价被误当成成交价，或绕过内部完整流程 | 明确商场价是参考价；内部仍从集成（线索/筛选）或加工（需求拆解）完整走 |
