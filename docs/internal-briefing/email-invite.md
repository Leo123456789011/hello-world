**背景**  
现行交付以销售接单、内部流转为主，需求拆解与方案制作耗时较多。现已形成三套方案：

1. 数据集成：标准数据项、可 API 交付。销售提需，PM 判定类型，销售筛选，系统报价出表。  
2. 数据加工：无标准项，由分析师生产、线下交付。需求结构化、产能确认、系统出报价方案；生产与审核仍由人工完成。  
3. 数据元素商场：客户自助选品（散装数据项、场景元件、数据包可同单购买），系统给出参考报价后提交销售。集成或加工由销售判定，再转入内部流程。商场报价非正式成交价。

商场为客户选品入口，集成与加工为内部履约路径。

**目的**  
1. 明确三套方案的分工与衔接。  
2. 明确各节点中 AI 与人工的职责。  
3. 听取意见，确定优先落地事项。

**拟解决的问题**  
1. 需求拆解、筛选、报价主要依赖手工，周期长。  
2. 集成与加工边界不清；客户不具备此项判断条件。  
3. 客户缺少自助选品与参考报价入口。  
4. AI 介入范围需先行界定，避免替代生产、审核及商务拍板。

**议程**  
1. 方案总述（10 分钟）  
2. 数据集成（10 分钟）  
3. 数据加工（10 分钟）  
4. 数据元素商场（15 分钟）  
5. 讨论（15 分钟）
