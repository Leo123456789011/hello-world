# 产业套保用户洞察与现货数据终端优化方案

> 角色：现货数据终端产品经理  
> 对象：产业套保用户（生产、加工、贸易、下游采购）  
> 目的：回答「需要什么数据与场景、终端要提供什么、客户水平如何、套保接受度如何」，并据此给出产品优化方案  
> 日期：2026-08-25

---

## 0. 一句话结论

产业套保用户买的不是「行情」，而是**把价格波动翻译成自己生意上的成本、库存、利润和敞口**。现货数据终端如果继续按金融终端逻辑堆指标，会服务好研究员、服务不好真正付钱的产业客户。优化方向应是：**场景优先、基差为核、分层交付、用现货语言讲套保**。

---

## 1. 用户是谁：不是一类人，是一条链上的四种角色

产业套保不是期货公司眼里的「套保户」，而是围绕真实货物流转产生的价格风险管理。同一条产业链上，目标和数据需求完全不同。

| 角色 | 典型企业 | 核心风险 | 套保方向 | 决策者真实问题 |
| --- | --- | --- | --- | --- |
| 上游生产 | 矿山、钢厂、电解铝、炼厂、种植加工 | 产成品价格下跌 | 卖出保值 | 这批货还能不能卖出利润？库存值不值钱？ |
| 中游加工 | 压榨、铜杆、镀锌、化工深加工 | 原料与成品价差收窄 | 压榨/加工利润锁定 | 开工还是停车？加工费/压榨利润够不够？ |
| 贸易商 | 钢贸、有色贸易、油脂油料、能源贸易 | 库存贬值、点价错配、资金占用 | 库存保值 + 基差贸易 | 现在该囤还是该出？点价窗口开不开？ |
| 下游采购 | 制造、家电、汽车、施工、食品 | 原料上涨、订单锁价后成本失守 | 买入保值 / 远期采购 | 现在锁价会不会买贵？锁多少、锁多久？ |

真正每天打开数据终端的人，通常不是「期货交易员」，而是：

1. **采购 / 销售**：看价、比价、谈价、点价
2. **期现岗 / 风控岗**（中大型企业才有）：对敞口、对基差、写日报
3. **财务 / 董办**：看套保效果、合规、审计口径
4. **老板 / 分管副总**：只看三件事——亏不亏、锁没锁住、会不会被说成投机

产品必须同时服务「盯盘的人」和「拍板的人」，但不能用同一套界面。

## 2. 产业套保用户到底需要什么数据

产业用户的数据需求可以分成四层。越往上越「金融」，越往下越「生意」。现货终端的护城河在下面两层，上面两层是连接器。

### 2.1 第一层：能成交的价格（刚需，每天用）

没有可信价格，后面一切套保都是空中楼阁。

- **区域现货价**：主流市场、主流规格、到厂/出厂/仓库价
- **厂提价 / 网价 / 成交价**：报价与真实成交要分开，产业用户最恨「有价无市」
- **升贴水 / 品牌升水 / 地区价差**：铜铝钢材油脂都靠这个谈合同
- **指数价 / 结算基准价**：合同挂钩钢联、SMM、卓创、普氏等，这是结算工具不只是参考
- **期货连续价 + 主力合约 + 远月结构**：只给一个主力价不够，产业要看近远月、换月、交割月
- **期现基差（现货 − 期货）**：这是产业用户的「操作系统」，不是附加图表

关键原则：**价格必须能对上合同口径**。用户问的不是「螺纹钢现在多少」，而是「我这个城市、这个规格、含税到厂、对标 2501 的基差是多少」。

### 2.2 第二层：能解释价格为什么动（高频决策）

产业用户不会先看宏观再看微观，他们先看自己库存旁边发生了什么。

- **库存**：社会库存、厂库、港口、交割库、仓单；最好能拆到地区和仓库
- **供应**：产量、产能利用率、开工率、检修、新投产
- **需求**：下游开工、订单、表观消费、季节性
- **成本与利润**：原料成本、加工费（TC/RC）、钢厂/压榨/冶炼利润、进口盈亏
- **进出口与货流**：海关、到港、洋山铜溢价、内外盘倒挂、海运运费
- **交割与仓单**：注册仓单、有效预报、品牌升贴水、交割成本
- **宏观与政策**：只保留能传导到该品种的（汇率、利率、出口退税、能耗双控、收储抛储）

产业用户真正用来做套保决策的，不是 200 个宏观指标，而是 **5–8 个能改变近月基差的基本面变量**。

### 2.3 第三层：能算自己账的数据（套保能否落地的分水岭）

市场数据再全，算不出「我公司现在敞口多少」，套保就停在看盘阶段。

- **自有库存**：库内、在途、厂内原料/在制品/成品
- **合同**：已签未执行采购/销售、点价未完成量、定价公式（期货 + 升贴水）
- **订单与排产**：未来 1–3 个月确定量和预估量
- **期货/期权头寸**：账户、合约、方向、套保属性、保证金
- **三口径基差**：
  - 市场基差：公开现货 − 期货
  - 订单基差：合同升贴水 vs 市场
  - 库存基差：持货成本 vs 当前可卖价格
- **净敞口**：未保值现货 + 未保值合同 − 期货对冲头寸（按品种、按月份、按事业部）
- **保值效果**：期现合并盈亏，而不是只看期货端浮亏

这一层是现货终端最容易缺、也最能形成差异化的部分。多数竞品停在「给你看市场」，产业客户卡在「对不上我的货」。

### 2.4 第四层：能过审计和老板关的数据（低频但决定续费）

- 套保方案、额度、止损、套保比率
- 每日结算快照、历史重算、操作留痕
- 会计口径：被套期项目、有效性测试、凭证
- 国资/上市公司披露口径：套保 vs 投机认定

没有这一层，国企和上市公司不敢把终端从「看数据」升级到「管风险」。

## 3. 核心使用场景（按生意节奏，而不是按菜单）

产业用户不会打开终端说「我要做套保分析」。他们是被具体业务事件推着走的。产品应按以下 8 个场景组织，而不是按「价格 / 库存 / 资讯」分栏。

### 场景 A：日常盯价与采销决策（使用频率最高）

- 今天这个规格在我所在区域涨了还是跌了？
- 厂价、市场价、期货谁先动？
- 对标竞品、对标上家报价差多少，能不能谈下来？

**终端要给的：** 我的品种 + 我的区域 + 我的规格的「今日价格条」，而不是全市场瀑布流。

### 场景 B：点价 / 基差贸易（贸易商和高阶产业户的核心）

- 升贴水该报多少？
- 对方给的升贴水贵不贵，历史分位在哪？
- 点价窗口内，基差是在走强还是走弱？
- 点完价后，期货腿有没有及时对冲？

**终端要给的：** 基差历史、季节性、分位数、升贴水报价板、点价倒计时、点价后自动提示对冲。

### 场景 C：库存保值（「货在手里会不会越放越亏」）

- 当前库存市值、持货成本、可变现价格
- 未套保库存量、已套保库存量
- 基差走弱时，是该抛期货、降价出货，还是移仓？

**终端要给的：** 库存市值看板 + 保值比例 + 「基差变动对库存盈亏的敏感度」。

### 场景 D：采购成本锁定（下游刚需）

- 订单已经锁了售价，原料还没买，敞口多大？
- 现在买入套保，锁定后的完整成本是多少（期货价 + 升贴水 + 运费 + 资金）？
- 锁 30%、50% 还是 80%？分批锁还是一次锁？

**终端要给的：** 「目标成本计算器」，输出的是「到厂完全成本」，不是希腊字母。

### 场景 E：销售锁价 / 加工利润锁定（上游和中游）

- 原料已买、产品未卖，加工利润还剩多少？
- 卖出套保后，吨利润能否盖过固定成本？
- 跨品种对冲是否可接受（如用螺纹对热卷、用豆粕对饲料企业）？

**终端要给的：** 利润公式模板（钢厂、压榨、冶炼、化工各一套），一键代入当日价格。

### 场景 F：换月、移仓、期限结构

- 近月交割临近，套保头寸要不要移？
- 移仓成本 vs 继续持有近月的交割/逼仓风险
- 远月升水时，是锁远期销售还是只锁近月？

**终端要给的：** 合约日历、移仓成本、期限结构图、交割品升贴水，而不是让用户自己翻行情软件。

### 场景 G：异常与风控（真正能留住付费的功能）

- 基差突破历史分位
- 库存超预警天数
- 敞口超董事会额度
- 进口盈亏由盈转亏
- 仓单急降 / 检修超预期

**终端要给的：** 按人推送的预警（微信/钉钉/短信），不是让人天天守着大屏。

### 场景 H：复盘、汇报、审计

- 这个月套保到底赚了还是亏了？（必须期现合并）
- 为什么期货亏了现货赚了？基差贡献多少？
- 能否导出给财务、董办、审计？

**终端要给的：** 一页纸套保日报 / 月报，语言是「锁定采购成本 12,350 元/吨，较未套保少亏 XX」，而不是「期货平仓亏损 XX 万」。

## 4. 使用数据终端时，用户希望有哪些类型的数据和功能

把期望拆成「数据」和「功能」两类。产业客户很少主动提产品功能名，他们用抱怨来表达需求。

### 4.1 他们嘴上要的数据

1. **「我这个品种、这个地方、这个规格」的价格**，不要全国一个数
2. **基差，而且要能选合约、选现货口径**
3. **库存和仓单，最好昨天的，不要上周的**
4. **利润和成本，能解释钢厂/炼厂为什么涨价或挺价**
5. **升贴水板和可成交量**，否则点价没有锚
6. **内外盘、汇率、进口盈亏**（有色、能源、农产品刚需）
7. **资讯要短、要跟品种绑定**，不要财经门户
8. **自己的合同、库存、头寸**（他们不一定说得清，但没有就无法从「看」走到「做」）

### 4.2 他们真正要的功能（按优先级）

| 优先级 | 功能 | 用户原话 | 产品形态 |
| --- | --- | --- | --- |
| P0 | 我的工作台 | 「一打开就看到我负责的那几个品种」 | 品种 × 区域 × 角色的首页，而不是数据目录 |
| P0 | 可信价格与基差 | 「别跟我合同对不上」 | 多口径价格、基差、升贴水、分位数 |
| P0 | 导出和 Excel | 「我最终还是要贴到表里给领导」 | Excel 插件、一键刷新、落地库/API |
| P0 | 预警 | 「不可能一直盯着」 | 阈值预警 + 异常检测 + 企业微信/钉钉 |
| P1 | 利润/成本计算器 | 「别让我自己 Excel 套公式」 | 行业模板：钢厂、压榨、电解铜、PTA 等 |
| P1 | 敞口与保值比例 | 「我到底盖没盖住」 | 库存/订单/期货三张表合成一张敞口表 |
| P1 | 点价助手 | 「升贴水历史和点价剩余量」 | 基差季节性 + 点价台账 |
| P1 | 套保效果一页纸 | 「别让老板只看到期货亏损」 | 期现合并盈亏、基差贡献拆解 |
| P2 | 研究工具 | 「偶尔要画图、对比季节性」 | 轻量图、季节性、相关、回归（默认隐藏高级项） |
| P2 | 协同与权限 | 「采购能看、财务能审、期货岗能下」 | 角色权限、审批流、操作留痕 |
| P2 | 投研/专家 | 「数据看不懂时有人讲」 | 品种早报、电话问询、AI 解读（必须可追溯到原始数据） |
| P3 | 交易下单 | 「能看盘顺便下最好，但我们可能已经有快期/CTP」 | 以对接为主，不要做成又一个交易终端 |

### 4.3 明确不要做成什么

- **不要做成 Mini Wind / Mini 彭博**：产业客户会被功能树吓跑，研究员才会迷路也愿意用。
- **不要做成期货交易软件**：交易执行有成熟玩家；现货终端的战场是定价、基差、基本面和敞口。
- **不要默认「越多数据越好」**：未清洗、不可比、不能对应合同的数据，是负资产。
- **不要用期货黑话做导航**：Delta、希腊值、最优套保比率可以放在高级层，默认层用「锁了多少货、还敞着多少」。

## 5. 大多数客户的水平如何

必须分层，否则产品要么太浅被贸易商嫌，要么太深被采购总监弃用。

### 5.1 能力金字塔（大约的市场结构）

```
L4 期现一体化团队     ~5%    贸易商头部、有色/油脂/黑色龙头
L3 有专职期现岗       ~15%   上市公司、大型民企、部分国企
L2 会看期货、偶尔套   ~40%   中型贸易、中型工厂采购/销售
L1 只做现货、怕期货   ~40%   中小贸易、地方工厂、施工/制造采购
```

比例因品种而异：有色、油脂油料、铜铝偏高；建材、煤炭、部分化工偏低。但**现货终端的付费大盘在 L1–L2**，口碑和标杆在 L3–L4。

### 5.2 各层真实能力与工具习惯

**L1：现货思维，Excel 是操作系统**

- 懂规格、运费、账期、进项票，不懂合约、保证金、移仓
- 每天看微信群报价、电话问价，终端用来「查个价、下个图」
- 把套保理解成「炒期货」；看到期货亏损就要求平仓
- 能接受的产品：价格、涨跌、库存、简报、计算器
- 不能接受：多合约、希腊值、策略回测、复杂权限

**L2：会看盘，不会管敞口**

- 知道基差，会口头说「基差走强/走弱」，但算不清自己的库存基差
- 套保决策靠老板一句话，比例拍脑袋（常见 30% 或 50%）
- 期货在一个软件，现货在终端，合同在 ERP，对账在 Excel
- 能接受：基差图、季节性、预警、简单敞口表
- 痛点：数据对不上、不会解释套保效果、怕被财务问责

**L3：有制度，缺工具**

- 有套保管理办法、额度、月度计划，执行仍大量手工
- 懂点价、升贴水、换月，需要三口径基差和审计留痕
- 终端当数据源，核心台账仍在 Excel / 自建系统
- 能接受：API、落地库、自定义指标、权限、日报模板
- 购买决策看：数据口径是否权威、能否对接内部系统、能否过内控

**L4：终端只是数据水管**

- 自建 CTRM / 期现系统，或使用快期、众期一类产业交易系统
- 需要的是高质量价格、库存、升贴水、仓单的 API 和一致性
- 对 C 端界面不敏感，对数据延迟、口径文档、历史可重算极敏感
- 现货终端很难靠页面「粘住」他们，要靠数据质量和生态位

### 5.3 产品含义

- **默认体验必须按 L1–L2 设计**：3 秒找到「我的价」，10 秒看懂「基差相对历史贵不贵」。
- **L3–L4 用模块和接口升级**，不要强迫所有人看见同一套复杂导航。
- **教育功能不是增值内容，是转化漏斗**：L1 → L2 的关键不是多卖一个套保模块，而是让人第一次算清楚「锁价后的完全成本」。

## 6. 对套保的接受度如何

接受度在提高，但**口头接受 ≠ 真会做，真会做 ≠ 敢做大**。产品不能假设用户已经认同套保哲学。

### 6.1 宏观上：接受度明显上升

- 价格波动、汇率波动、利润变薄，倒逼企业从「靠判断行情」转向「锁利润」。
- 《期货和衍生品法》、套保会计与信披规则完善，上市公司参与套保的家数持续增加（2024 年 A 股非金融类参与套保约 1500 家量级）。
- 有色、家电、化工、油脂等产业链参与率显著高于一般制造业；有色龙头已从单向卖出保值，走向基差贸易、含权贸易、利润锁定。
- 基差贸易和点价在铜、铝、钢材、豆粕、能源化工中已成为「做生意的方式」，而不只是「额外的金融操作」。

### 6.2 微观上：分层极严重，障碍非常具体

| 障碍 | 表现 | 对产品的含义 |
| --- | --- | --- |
| 认知障碍 | 「套保就是亏钱」「期货亏了就是乱做」；媒体常单边报道期货亏损 | 效果展示必须期现合并，默认用现货语言 |
| 组织障碍 | 采购要低价、销售要高价、期货岗要合规、财务要凭证，考核互相打架 | 需要角色视图和「套保效果」共同 KPI 口径 |
| 能力障碍 | 中小企业没有专职人员；决策靠老板盘感 | 要有「傻瓜套保」路径：锁多少、锁多久、现在贵不贵 |
| 合规障碍 | 国企「明确支持、严格管控」；超额度、方向做错会被追责 | 额度、套保认定、留痕是功能不是附加 |
| 工具障碍 | 期现数据割裂，Excel 对账 2–3 小时/日，敞口滞后 10–30 分钟 | 统一口径比再做一个图更值钱 |
| 策略障碍 | 绝大多数企业只会最基础的期现一一对应；跨品种、价差、期权用得少 | 先把简单套保做对，再给进阶工具 |

### 6.3 可执行的接受度判断（用于销售和产品分层）

- **高接受**：有色、油脂油料、铜铝加工、大型钢贸/矿贸、上市制造业的原料采购。他们要深度：基差、点价、API、敞口。
- **中接受**：钢厂、化工、煤炭、农产品加工。认同套保，但制度、人才、考核没跟上。他们要「半套保」：利润测算、锁价建议、预警、一页纸汇报。
- **低接受**：中小贸易、地方工厂、施工企业采购。怕期货，但极度需要价格和库存。他们要现货能力；套保只能以「锁成本/锁利润计算器 + 教育」切入，不能一上来卖交易。

一个现实的产品策略：**不要对低接受客户推销套保，要对他们推销「少买贵、少卖便宜、库存别坐电梯」**。套保是手段，稳态利润才是他们听得懂的价值。

## 7. 现货数据终端的典型问题（对标后的自我诊断）

市面上钢联、SMM、卓创等已经把「价格 + 基本面」做到足够深。产业交易终端（快期等）在下单、点价、移仓上更强。现货数据终端夹在中间，最容易出现这些问题：

1. **目录型信息架构**：按品种 → 价格/库存/资讯切，用户要自己拼场景。
2. **基差是图表，不是工作流**：能看不能用，不能选合同口径，不能接自己的货。
3. **只有市场数据，没有「我」的数据**：于是用户永远活在 Excel。
4. **面向研究员的分析深度 × 面向采购的操作效率，两头不到位。**
5. **预警弱、移动弱、协同弱**：产业决策发生在微信群和早会上，不在 PC 终端里。
6. **套保模块要么没有，要么一上来就是金融产品**，L1/L2 直接流失。
7. **数据口径文档不足**：L3/L4 不敢接 API，因为不知道这个价格到底是什么价。

## 8. 优化方案

### 8.1 产品原则

1. **先场景，后数据。** 导航按「盯价 / 点价 / 库存 / 锁成本 / 锁利润 / 风控 / 汇报」，数据藏在场景后面。
2. **基差是一等公民。** 任何价格都默认带：对应合约、升贴水、历史分位、昨日对比。
3. **用现货语言讲风险管理。** 默认文案是「未锁原料 3,200 吨，按今日价格，成本敞口约 XX 万」；「套保比率」放高级选项。
4. **分层，不分裂。** 同一套数据，三层皮肤：看价版、经营版、期现版。
5. **Excel 不是敌人，是第一工作台。** 插件和导出做好，比再做一个复杂 BI 更能留住 L1–L3。
6. **预警 > 看板。** 产业用户没有专职盯盘编制，错过 30 分钟就是真金白银。
7. **不和交易软件抢执行，和它们做连接。** 现货终端的终局是「定价与风险操作系统」，交易可以跳转或对接。

### 8.2 产品架构：三个版本，一条数据中台

```
                    ┌─────────────┐
                    │  数据中台    │  价格/库存/利润/仓单/资讯
                    │  + 口径字典  │  合同口径映射、单位、含税、交割品
                    └──────┬──────┘
           ┌───────────────┼───────────────┐
           ▼               ▼               ▼
     看价版 (L1)      经营版 (L2)      期现版 (L3/L4)
     我的价格条       利润/成本计算     三口径基差
     区域升贴水       点价台账         敞口引擎
     库存与简报       预警订阅         API / 落地库
     锁价计算器       套保一页纸       权限 / 留痕 / 审计
```

**看价版**：解决「每天打开能用」。目标是替代微信群查价的一部分，而不是替代交易。

**经营版**：解决「把市场数据变成经营决策」。这是现货终端的主战场，也是把 L2 客户做成 ARR 的关键。

**期现版**：解决「对得上货、过得了审计」。可以与 CTRM、ERP、交易终端共存，不追求替代。

### 8.3 关键功能优化（按场景落地）

#### （1）「我的工作台」替代首页数据堆

用户首次进入只问四件事：品种、区域、角色（采购/销售/贸易/风控）、关注规格。之后首页固定为：

- 今日我的价格（现货 / 期货 / 基差 / 升贴水）
- 库存与仓单变化
- 成本或加工利润
- 3 条跟该品种相关的短讯
- 我的敞口（若已接入自有数据；未接入则展示「未锁量估算」引导）

去掉「全市场热力图」作为默认首页。热力图可以留在发现页。

#### （2）基差工作台（P0）

必须支持的口径，而不是一张图：

- 现货选择：市场价 / 厂提价 / 指数价 / 用户合同价
- 期货选择：主力 / 指定合约 / 加权
- 展示：绝对基差、基差率、历史分位、季节性、与库存/仓单的叠加
- 动作：设预警、导出、生成点价建议（「当前升贴水高于近 3 年 80% 分位」）

对贸易商，这是留存功能；对工厂，这是教育功能。

#### （3）经营计算器（把套保从概念变成算术）

内置可改公式的模板，输出业务结果：

- 下游采购：锁定后到厂完全成本 = 期货 + 升贴水 + 运费 + 资金成本 + 损耗
- 上游销售：锁定后出厂净价
- 加工：压榨/炼厂/钢厂吨利润
- 贸易：持货利润 = 现货变动 + 期货盈亏 + 升贴水变动 − 仓储资金

每一条结果旁边给一个按钮：**「若锁 XX%，对应期货手数约 X 手」**。这是 L1→L2 的转化钩子，不是交易功能本身。

#### （4）轻量敞口，不先做 CTRM

不要一上来做全量期现系统。先做「三张表合成」：

1. 库存表（可 Excel 导入）
2. 未执行合同表（点价量、定价公式）
3. 期货持仓表（可手工录、可对接）

输出：按品种、按月份的净敞口、保值比例、额度占用。对账时间从小时级降到分钟级，就已经能说服 L2/L3 付费。ERP 深度对接放到期现版。

#### （5）预警与移动，按人而不是按数据

预警规则用业务语言配置：

- 「我的螺纹基差弱于 −200」
- 「电解铜社会库存周增超 5%」
- 「未锁原料超过本月采购计划 30%」
- 「进口盈亏转负」

通道：企业微信 / 钉钉 / 短信优先于 App 推送。产业客户活在微信，不活在又一个 App。

#### （6）套保沟通组件（专门解决接受度）

做一个「套保效果一页纸」：

- 现货端盈亏（库存市值 + 合同）
- 期货端盈亏
- 基差贡献
- 合并结果 vs 完全不套保的结果

默认分享格式适配老板：大字、少表、有结论。这能直接降低「期货亏了就被叫停」的组织风险，是提升套保接受度最有效的产品手段。

#### （7）数据可信度与口径字典（给 L3/L4 的护城河）

每一条价格序列必须可点开看到：

- 采集时间、样本、含税、单位、规格、交货地、升贴水定义
- 与主流合同挂钩关系（是否可作为结算参考）
- 历史修订记录（能不能重算）

没有口径字典，API 卖不进核心客户；有了口径字典，才有资格做「合同基准价」生态。

#### （8）内容与教育：用场景课，不用期货教材

- 每日「品种 60 秒」：价格、基差、库存、一句结论
- 「什么时候该锁价」卡片：基于分位和库存，而不是喊单
- 角色路径：采购如何锁成本、贸易如何做基差、工厂如何锁利润
- AI 解读可以做，但必须点回原始序列，禁止黑盒喊涨跌

### 8.4 数据策略优化

现货终端的竞争不在「再多 10 万条指标」，而在 **少而准、能对账、能进合同**。

1. **做深 20% 核心序列**：每个重点品种锁定「价格、基差、库存、利润、仓单、进出口」六件套，日更、可追溯。
2. **区域与规格颗粒度优先于全国指数**：产业客户为「能对上自己货」付费。
3. **升贴水和成交样本是差异化**：只有报价没有成交，点价场景站不住。
4. **期货数据以对接为主**：连续合约、期限结构、仓单、持仓变化要有，但不必自研交易行情中台。
5. **开放「我的数据」入口**：Excel、API、ERP，先接进来，再谈智能化。

### 8.5 商业与获客优化

| 客户层 | 卖什么 | 怎么转化 | 不要怎么卖 |
| --- | --- | --- | --- |
| L1 | 看价版 + 锁价计算器 | 用「少买贵」案例，不谈套保 | 不要演示复杂期现系统 |
| L2 | 经营版（基差+预警+一页纸） | 用一次复盘会证明「老板能看懂」 | 不要按金融终端按模块报价 |
| L3 | 期现版 + 日报模板 + 权限 | 跟风控/财务一起试点一个品种 | 不要承诺替代 ERP |
| L4 | 数据 API / 落地库 / 口径 SLA | 按序列质量和稳定性签约 | 不要靠 UI 打动 |

销售话术统一成三句，对应三个接受度：

1. 低接受：「帮你看清今天该不该买、库存值不值钱。」
2. 中接受：「帮你算清锁了之后真实成本，以及没锁的敞口。」
3. 高接受：「帮你把市场基差、订单基差、库存基差对成一本账。」

### 8.6 优先级（按价值密度，不按工期）

**立刻做（能改变默认体验）**

1. 我的工作台（品种/区域/角色）
2. 多口径基差 + 分位 + 预警
3. Excel 插件稳定增量刷新
4. 锁价/利润计算器（先做 3–5 个标杆品种）
5. 套保效果一页纸（即使敞口先靠导入）

**接着做（能拉开经营版）**

6. 轻量敞口（三张表）
7. 点价台账与升贴水历史
8. 企业微信/钉钉预警
9. 口径字典与数据血缘
10. 品种早报（人 + 规则，再上 AI）

**有了客户再做（避免过早做成 CTRM）**

11. ERP/交易终端对接
12. 审批流、套保额度、会计凭证
13. 跨品种对冲与期权结构
14. 卫星/货流等增强数据（只放进已有场景，不新开「炫技首页」）

## 9. 成功标准（产品经理怎么判断优化有没有用）

不要用「指标覆盖数」「DAU」单独衡量产业终端。建议看这组指标：

1. **3 分钟到达率**：新用户 3 分钟内是否看到「自己的品种 + 自己的区域价格 + 基差」。
2. **工作台留存**：首页是工作台的用户，次日/7 日留存是否显著高于目录浏览用户。
3. **Excel 插件周活跃**：L2/L3 是否把终端当数据源嵌入周报。
4. **预警触达后的回访率**：被推送的人是否在 24h 内打开对应序列。
5. **计算器使用 → 经营版升级**：L1 用户使用锁价计算器后的付费转化。
6. **一页纸被转发次数**：这是套保接受度在组织内改善的代理指标。
7. **核心序列投诉率**：价格口径被客户质疑的次数（下降才是质量提升）。
8. **API 客户的重算一致性**：历史数据被修订后能否对账。

## 10. 给产研的最终建议

产业套保用户要的数据，按重要性排序是：

**能对上合同的现货价 → 基差与升贴水 → 库存/仓单 → 成本利润 → 自己的货与敞口 → 宏观与资讯。**

他们要的功能，按重要性排序是：

**我的工作台 → 查价与导出 → 基差 → 预警 → 经营计算 → 轻量敞口 → 给老板的一页纸 → 接口与合规。**

大多数客户的水平是 **现货熟练、期货半懂、套保不敢做大**。接受度在龙头品种和大企业中已经很高，但在数量最多的中小客户里，套保仍被理解成投机。现货数据终端不该假装自己是交易系统，也不该只做研究员数据库。

**正确位置是：产业经营的价格操作系统。**  
先让客户看懂今天的价和基差，再让他们算清锁不锁、锁多少，最后才把敞口、审计和交易连接补齐。谁先把「市场数据」翻译成「我这单货的盈亏」，谁就能在产业客户里把现货终端从工具做成习惯。
